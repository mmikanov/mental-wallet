# Bug 4 Review — Unsubscribed reported as "Unsubscribed", not "Waiting"

Spec: `1.0.6-bug-fixes` · Wave 1 · Reporting-only worker change

## Scope reviewed
Diff of `messaging-worker/src/index.ts`, `messaging-worker/src/dripSummary.ts`,
`messaging-worker/src/dripSummary.test.ts` (and `drip.test.ts`, which has no changes).
`git status` confirms no other production worker files changed for this task.

## Verification against intent

1. **Branch ordering (CRITICAL).** In `runDripPass` (index.ts ~line 1596) the
   `resolved.kind === 'unsubscribed'` branch is placed BEFORE
   `if (resolved.kind === 'waiting' || !resolved.campaign)`. Because an unsubscribed result
   carries a `campaign`, the `!resolved.campaign` guard would not catch it; placing it first
   prevents it being swept into `waiting`. Confirmed correct, with an explanatory comment.

2. **`resolveNextForSubscriber` distinctions.** Only the `!scopeOptedIn` path returns
   `{ kind: 'unsubscribed', campaign }` (index.ts ~line 1271). The missing-campaign case
   (`return { kind: 'waiting' }`) and the within-gap case (`return { kind: 'waiting', campaign }`)
   both remain `'waiting'`. Matches the design decision exactly. The inline kind union gained
   `'unsubscribed'`.

3. **Waiting no longer counts unsubscribed.** `runDripPass` adds a dedicated `unsubscribed`
   counter and a `status: 'unsubscribed'` plan entry, and returns `unsubscribed` alongside
   `sent/failed/skipped/finished/waiting`. The `waiting++` path is only reached for genuine
   waiters.

4. **Send path untouched.** The send path (`kind === 'next'`, `sendOneDrip`) is unchanged;
   no new branch alters who receives email. The change is reporting-only.

5. **Type threading.** `PlanStatus` gained `'unsubscribed'`; `SummaryPlanEntry.status` and
   `SummaryCounts.unsubscribed` added in dripSummary.ts; `sendDripSummaryEmail` threads
   `unsubscribed` through into `buildDripSummary` counts. `runDripPass` and
   `sendDripSummaryEmail` return/param types updated consistently.

6. **Summary rendering.** An "Unsubscribed" total line is rendered in BOTH the text block
   (`Unsubscribed: ${counts.unsubscribed}`) and the HTML block
   (`Unsubscribed: <strong>${counts.unsubscribed}</strong>`), positioned between Waiting and
   Finished in each.

7. **Unchanged files.** `drip.ts`, `adminHelpers.ts`, and `drip.test.ts` are unchanged
   (`git diff --stat` empty). `kind` is worker-local; adminHelpers' SimCell/SimPlanEntry is a
   separate simulation type, correctly left alone.

8. **Tests present.** Tasks 4.1 (exploration) and 4.2 (preservation) live in
   `dripSummary.test.ts`. 4.1 asserts the unsubscribed person is reported under "Unsubscribed"
   (text + HTML) and NOT folded into "Waiting"; 4.2 asserts existing sent/failed/waiting/
   finished classification and per-campaign grouping are unchanged.
